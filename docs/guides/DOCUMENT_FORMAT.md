# DOCUMENT FORMAT — 文档格式规范

| 属性 | 值 |
|:---|:---|
| 文档状态 | specified |
| 最后更新 | 2026-09-08 |
| 适用范围 | 仓库内 Markdown 文档 |
| 不负责 | 事实归属、冲突裁决和 ADR 触发条件 |

本文只定义文档的结构、编号、表达和冗余边界。事实归属与维护流程由
[DOCUMENT_GOVERNANCE](DOCUMENT_GOVERNANCE.md) 定义，架构取舍由
[ADR 治理规则](../decisions/README.md) 定义。

## 1. 通用格式

### 1.1 标题与元数据

- 每个文件只允许一个 H1；权威文档优先使用 `# 英文标识 — 中文标题`，ADR 使用 `# ADR-NNN — 标题`，目录索引可保留中文标题；
- 权威规范、模块文档、计划和指南在 H1 后放元数据表，字段按“文档状态、最后更新、适用范围、不负责、相关决策”排序，无值字段不占位；
- 规范与计划状态使用 `observed / proposed / specified / implemented / verified / deprecated / retired`；ADR 使用 `proposed / accepted / deprecated / superseded`；
- README、CHANGELOG、AGENTS.md 和 CLAUDE.md 可使用各自专用头部，不强制元数据表。

### 1.2 标题层级与编号

- 权威规范、模块文档和指南的 H2 使用连续整数：`## 1. ...`、`## 2. ...`；不得跳号；ADR、ROADMAP、CHANGELOG 和 README 按各自稳定模板组织；
- H3 在同一 H2 下存在两个及以上并列主题时使用 `### 2.1 ...`、`### 2.2 ...`；只有一个子主题时直接写入 H2；
- H4 只用于 H3 内确有两个及以上并列子主题的长章节；不得用加粗段首模拟标题；
- 标题编号表达文档结构，不表达版本、优先级或实施顺序；
- ADR 使用固定语义标题，不手工编号章节；选项使用 `### 方案 A`、`### 方案 B`；
- ROADMAP 使用连续整数里程碑 `M0`、`M1`、`M2`，不得新增小数里程碑。

### 1.3 段落、列表与表格

- 一个段落只表达一个主题，超过 5 句时拆成小节、列表或表格；
- 并列要求使用无序列表，严格顺序使用有序列表，状态映射或字段对照使用表格；
- 同一列表的条目使用一致语法和标点；完整句以中文分号结尾，最后一项以句号结尾；短语列表不加句末标点；
- 表格每行只表达一个可独立审查的事实；
- 命令、Schema、状态机和目录树使用代码块，不得用代码块承载普通说明文字。

### 1.4 链接与引用

- 首次引用本仓文档时使用相对链接；后续可使用稳定文档名或章节号；
- 跨文档只引用权威事实，不复制整段定义；
- 章节改号时必须同步仓库内全部引用；文件移动时必须同步目录索引和反向链接；
- 不使用裸路径代替可点击链接，代码文件或命令中的路径除外。

## 2. 内容组织与冗余

### 2.1 单一职责

| 文档类型 | 只回答 | 不得承载 |
|:---|:---|:---|
| ADR | 为什么选择该长期方案 | 当前施工清单、重复完整规范 |
| 规范 / 模块文档 | 当前有效目标、边界、失败语义、验收门禁 | 讨论过程、逐次提交记录 |
| ROADMAP | 里程碑目标、范围、依赖、退出门禁 | 测试用例、逐批操作步骤 |
| TESTING | 必须验证的场景、环境与阈值 | 未执行的通过声明 |
| TEST_EXECUTION | 命令、执行批次、结果记录方法 | 产品事实、架构取舍 |
| CHANGELOG | 已发生变化及实际验证 | 未来计划、未执行结果 |
| README | 导航、入口、最短使用说明 | 专项规范正文 |

### 2.2 投影长度

- 非权威文档对同一事实最多保留 1 个摘要段或 3 个摘要条目，并链接权威来源；
- 实施批次、验收矩阵、字段定义和状态机只能各有一个完整版本；
- 历史背景只保留在 ADR 和 CHANGELOG，规范正文只保留影响当前行为的结论；
- 同一文档出现第二份相同清单时，保留职责最匹配的一份，其余改为链接。

### 2.3 当前态与目标态

- `observed`、`proposed`、`specified` 和已实现状态必须分段或分表展示；
- proposed 内容必须在标题或元数据中标识，不能混入 accepted 或 specified 条目；
- 完成状态只在 ROADMAP 汇总、CHANGELOG 取证；规范只声明当前有效行为和尚未实现的已批准目标。

## 3. 文档类型模板

### 3.1 权威规范、模块文档与指南

```text
# NAME — 中文标题

元数据表

职责声明 / 导航

## 1. 目标与范围
## 2. 核心定义或结构
## 3. 行为、边界或执行规则
## 4. 失败与安全语义
## 5. 验收或验证
## 6. 当前状态与门禁
## 7. 变更治理
```

可按主题增加或合并章节，但同一文档内编号必须连续，章节顺序保持“定义 → 行为 → 约束 → 验收 → 状态”。

### 3.2 ADR

```text
# ADR-NNN — 标题

元数据表：状态、日期、决策人、相关决策

## 背景
## 决策问题
## 备选方案
### 方案 A
### 方案 B
## 决策
## 边界
## 后果
## 验收条件
## 修订记录
```

- accepted ADR 不保留“候选”“建议采用”等未决措辞；
- 修订写入同一“修订记录”，当前有效决策只在“决策”和“边界”各定义一次；
- 被替代 ADR 保留历史内容并标记 `superseded`，不得重写为当前规范。

### 3.3 ROADMAP

每个里程碑统一使用：

```text
## M7 里程碑名称（阶段 · 状态）

目标：一句话。

范围：
- ...

依赖：一句话或短列表。

退出门禁：
- [ ] ...
```

实施步骤不进入 ROADMAP，应放入临时计划或对应执行记录。

### 3.4 README 与目录索引

- 根 README：项目定位、最短启动路径、文档入口；
- 目录 README：本目录职责、文件索引、阅读顺序；
- 模块 README：模块职责、边界、启动与验证命令；
- README 不复制规范、ADR 或完整环境指南。

### 3.5 CHANGELOG

- 新条目放在当前分类顶部，一级变更条目必须带实际日期 `（YYYY-MM-DD）`；
- 每条只记录一个逻辑变化，可包含范围、验证和状态，不写后续待办清单；
- 实际命令和结果必须与本次执行一致，未运行内容不得写成通过。

## 4. 格式验收

文档变更至少满足：

- [ ] H1 唯一，标题层级不跳级；
- [ ] 需要编号的 H2/H3 连续且与父级一致；
- [ ] 没有用加粗段首模拟标题；
- [ ] 当前态、目标态和历史没有混写；
- [ ] 同一事实、清单或表格只有一个完整来源；
- [ ] ROADMAP、TESTING、TEST_EXECUTION 和 CHANGELOG 职责未混用；
- [ ] 新增或改号章节的链接已同步；
- [ ] `bash scripts/check-document-format.sh`（默认只检查当前变更；全仓库盘点使用 `--all`）和 `git diff --check` 通过。
